# Cloud Computing CA2 – Announcements Platform

A small cloud-native web application for publishing and viewing announcements. It demonstrates a three-tier architecture deployed across managed cloud platforms: a static frontend on **Vercel**, a REST API on **Render**, and a document database on **MongoDB Atlas**.

## Project Overview and Objectives

The application lets a user publish short announcements (a title and a message) and see all published announcements, newest first. It also shows live backend and database connectivity status.

Objectives:

- Design and deploy a multi-tier application using cloud platform services.
- Separate presentation (frontend), application logic (backend API) and data storage (database).
- Expose a simple REST API consumed by a browser-based client.
- Keep configuration and secrets out of source control by using environment variables.
- Use managed hosting with Git-based continuous deployment.

## Architecture

```
┌────────────────────┐   HTTPS (fetch / JSON)   ┌──────────────────────┐   Mongoose    ┌──────────────────────┐
│  Frontend          │ ───────────────────────► │  Backend API         │ ────────────► │  Database            │
│  Vercel            │ ◄─────────────────────── │  Render (Node.js)    │ ◄──────────── │  MongoDB Atlas       │
│  HTML / CSS / JS   │                          │  Express REST API    │               │  ca2database         │
└────────────────────┘                          └──────────────────────┘               │  announcements       │
                                                                                       └──────────────────────┘
```

### Frontend (`frontend/`)

A static single-page client made of `index.html`, `style.css` and `script.js`. It is hosted on Vercel (project `cloud-computing-ca2-frontend`). It calls the backend with the browser `fetch` API to:

- check backend and database status on load,
- list announcements,
- publish a new announcement.

### Backend (`backend/`)

A Node.js / Express application (`server.js`) hosted on Render (service `cloud-computing-ca2-api`). It enables CORS so the Vercel-hosted frontend can call it, parses JSON request bodies, validates input, and uses Mongoose to read and write MongoDB. The server reads its configuration from environment variables and only starts listening after the database connection succeeds.

### Database

MongoDB Atlas hosts the database `ca2database`. Announcements are stored in the `announcements` collection with this document shape:

| Field       | Type   | Notes                          |
| ----------- | ------ | ------------------------------ |
| `_id`       | ObjectId | Generated by MongoDB         |
| `title`     | String | Required                       |
| `message`   | String | Required                       |
| `createdAt` | Date   | Defaults to the creation time  |

## Technologies Used

- **Frontend:** HTML5, CSS3, vanilla JavaScript (Fetch API)
- **Backend:** Node.js, Express 5, Mongoose, CORS, dotenv
- **Database:** MongoDB Atlas
- **Hosting:** Vercel (frontend), Render (backend), MongoDB Atlas (database)
- **Source control and CI/CD:** Git and GitHub with platform auto-deploy from the `main` branch
- **Tooling:** nodemon (development)

## API Endpoints

Base URL: the public URL of the Render service (`cloud-computing-ca2-api`).

### `GET /api/health`

Reports backend status and database connectivity.

Example response:

```json
{
  "status": "success",
  "message": "Backend is working",
  "database": "Connected"
}
```

`database` is `"Connected"` or `"Disconnected"`.

### `GET /api/announcements`

Returns all announcements as a JSON array, sorted by `createdAt` (newest first).

- `200 OK` – array of announcement documents
- `500 Internal Server Error` – `{ "message": "<error>" }`

### `POST /api/announcements`

Creates a new announcement.

Request body (JSON):

```json
{
  "title": "Example title",
  "message": "Example message"
}
```

Responses:

- `201 Created` – `{ "message": "Announcement published successfully", "announcement": { ... } }`
- `400 Bad Request` – `{ "message": "Title and message are required" }`
- `500 Internal Server Error` – `{ "message": "<error>" }`

## How the Components Communicate

1. The user opens the frontend served by **Vercel**.
2. The browser runs `script.js`, which sends HTTPS requests directly to the **Render** backend (the base URL is set in the `API_URL` constant in `frontend/script.js`).
3. The Express API handles the request and uses **Mongoose** to query or write the `announcements` collection in **MongoDB Atlas**.
4. The API returns JSON to the browser, and the frontend updates the page.

The frontend never talks to MongoDB directly. Only the backend holds database credentials, supplied through environment variables on Render. CORS is enabled on the API so cross-origin requests from the Vercel domain are accepted.

## Deployment Platforms

| Layer    | Platform      | Resource                         |
| -------- | ------------- | -------------------------------- |
| Frontend | Vercel        | `cloud-computing-ca2-frontend`   |
| Backend  | Render        | `cloud-computing-ca2-api`        |
| Database | MongoDB Atlas | `ca2database` / `announcements`  |

Both Vercel and Render are connected to this GitHub repository and can build and deploy automatically when changes are pushed to `main`.

## Setup Instructions

### Prerequisites

- Node.js (current LTS recommended) and npm
- A MongoDB Atlas cluster with a database user and network access configured
- Accounts on GitHub, Vercel and Render

### Run the backend locally

```bash
cd backend
npm install
```

Create a `backend/.env` file (never commit it; it is excluded by `.gitignore`) with:

```
MONGODB_URI=<your MongoDB Atlas connection string>
PORT=5000
```

Then start the server:

```bash
npm start        # production-style start
npm run dev      # auto-reload with nodemon
```

Verify it is running by opening `http://localhost:5000/api/health`.

### Run the frontend locally

The frontend is static. Serve the `frontend/` folder with any static file server (for example, the VS Code Live Server extension, or `npx serve frontend`). To use a local backend, change the `API_URL` constant at the top of `frontend/script.js` to `http://localhost:5000`.

### Deploy the backend to Render

1. Create a **Web Service** from this GitHub repository, branch `main`.
2. Set the root directory to `backend`.
3. Build command: `npm install`. Start command: `npm start`.
4. Add the environment variable `MONGODB_URI` in the Render dashboard (do not store it in the repository).
5. In MongoDB Atlas, allow network access from Render so the API can connect.

### Deploy the frontend to Vercel

1. Import this GitHub repository as a new Vercel project, branch `main`.
2. Set the root directory to `frontend` (no build step is required for a static site).
3. Make sure `API_URL` in `frontend/script.js` points to the deployed Render service.

## Security Notes

- No credentials, API keys, tokens or connection strings are stored in this repository.
- Database credentials are provided only through environment variables on the hosting platform.
- Keep `.env` files out of version control.
